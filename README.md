# True Tribute — Custom Pendant Design

An internal tool for **True Tribute by Prabu Jewellery**. The operator uploads
a customer's photo once and gets everything needed to list and make a custom
photo pendant:

1. **An engraving sketch** — bold black-and-white line art of the people (or
   pet) in the photo, generated by Google Gemini.
2. **An instant preview** of that sketch as any pendant in the catalogue, in
   silver or gold.
3. **A photorealistic product photo** of the finished pendant, for the
   e-commerce listing.
4. **Manufacturing files** — 3DM (Rhino), DXF (laser cutter) and SVG.

```bash
npm install
cp .env.example .env.local   # then add your real GEMINI_API_KEY
npm run dev                  # http://localhost:3000
```

Get a key from [Google AI Studio](https://aistudio.google.com/apikey). Billing
must be enabled on the key's Google Cloud project — image-output models have
no free-tier allowance, so a `429` quota error means billing, not a bug.

## Workflow

| Step | What the operator does | What happens |
|---|---|---|
| 1. Upload Photo | Drag in or browse to a JPG / PNG / WEBP (max 8 MB) | Checked in the browser, then re-checked on the server by its actual bytes |
| 2. Choose Category | Face, Half Size, Couple, Family or Pet | Selects how Gemini frames the sketch (e.g. Face crops at the jaw; Couple keeps both people) |
| — | Click **Generate Sketch** | **AI call #1** (~10–15 s) |
| 3. Master Sketch | Review; regenerate if needed | The sketch is cropped to the ink and its background made transparent |
| 4. Pendant Type | **Silhouette Cut** or **Shape Pendant** | Silhouette Cut traces its cut outline and hanging ring from the sketch |
| 5. Metal | Silver or Gold | — |
| 6. Preview | Compare metals side by side | Rendered instantly in the browser |
| 7. Customize | Zoom, rotate, move the artwork | Rendered instantly in the browser |
| 8. Product Mockup | Click **Render Silver / Gold mockup** | **AI call #2**, once per metal clicked (~13 s) |
| 9. Manufacturing Files | Click **Prepare manufacturing files** | 3DM, DXF and SVG, no AI |
| 10. Download Preview | Pick the sketch or a metal preview | Transparent PNG, no AI |

**Cost per design:** one AI call for the sketch, plus one for each mockup
rendered. Choosing shapes and metals, adjusting, previewing and exporting are
all free and instant — nothing in steps 4–7 or 9–10 can trigger an AI call.
The sketch and settings survive a page reload (session storage); the original
photo does not.

## Pendant types

**Silhouette Cut** — the catalogue's Face, Half Size, Couple, Family and Pet
pendants. The metal is cut along the artwork's own outline, a small margin
outside the ink, with a hanging ring merged into the top centre. This matches
the client's reference production files: one red cut outline around the
artwork plus two concentric circles for the ring and its hole.

The outline is traced from the **sketch**, never from the photo. Gemini
re-frames and re-proportions people when it draws them, so an outline traced
from the photo describes a different picture than the one being cut.

**Shape Pendant** — the catalogue plates: Round, Oval, Heart, Bar, Tag and
Octagonal, with the artwork engraved on the plate. Heart and Round can also
have a red or blue enamel rim ("Heart with Color" / "Round with Color").

## Outputs

| Output | Format | Made by | Use |
|---|---|---|---|
| Engraving sketch | PNG, transparent | Gemini + pixel clean-up | Reference artwork |
| Product mockup | PNG / JPEG | Gemini, from a flat render of the exact design | E-commerce listing |
| Manufacturing files | **3DM**, **DXF**, SVG | Vector tracing, no AI | Rhino / laser cutter |
| Preview image | PNG, transparent | Browser canvas | Quick share |

The manufacturing files contain two layers, in millimetres at a default width
of 25 mm (rescale freely in your software):

- **CUT** (red) — the pendant outline; for Silhouette Cut also the ring hole.
- **ENGRAVE** (black) — the artwork, traced to closed curves.

They are 2D curves only, with no relief or depth; extruding and finishing is
done in Rhino. The DXF and 3DM contain identical geometry.

Always check each AI mockup before posting it. The prompt forbids changes
to the engraving and any added text or hallmarks, but the result comes from
an image model.

## Configuration

`.env.local` (server-only — never prefix these with `NEXT_PUBLIC_`):

| Variable | Required | Purpose |
|---|---|---|
| `GEMINI_API_KEY` | Yes | Sketch generation and product mockups |
| `REMOVE_BG_API_KEY` | No | Only used by a parked, unwired feature (see below) |
| `DIECUT_URL`, `DIECUT_TOKEN` | No | Not used by the app (see below) |

Tuning constants:

| What | Where |
|---|---|
| Cut margin and ring size for Silhouette Cut (3.5% and 7% of the sketch) | `lib/edge-cut-contour.ts` |
| Default physical width of exported files (25 mm) | `lib/laser-export.ts` |
| Sketch style and category framing prompts | `lib/gemini.ts` |
| Mockup prompt | `lib/mockup.ts` |
| Shapes, metals, rim colours | `lib/pendant-shapes.ts`, `lib/materials.ts` |
| Upload types and size limit | `lib/validation.ts` |

## How it works

```
Browser                                   Server                               Google Gemini
───────                                   ──────                               ─────────────
Upload + category ──────────────────────▶ POST /api/generate-image
                                            validate bytes → lib/gemini.ts ──▶ photo → sketch
                                            lib/image-processing.ts        ◀──
◀── master sketch (data URL) ─────────────  (crop, transparent background)

lib/edge-cut-contour.ts traces the cut outline + ring from the sketch
components/PendantPreview.tsx paints every preview on a canvas

Render mockup ──────────────────────────▶ POST /api/render-mockup
                                            lib/mockup.ts: flat composite  ──▶ composite → photo
◀── product photo ────────────────────────                                ◀──

Prepare files ──────────────────────────▶ POST /api/export-laser
                                            lib/laser-export.ts (sharp + potrace)
◀── SVG + DXF + 3DM ──────────────────────  lib/dxf-writer.ts, lib/rhino-export.ts
```

All shape maths lives in `lib/pendant-geometry.ts`. The canvas preview, the
mockup composite and the manufacturing files all take the outline and the
artwork placement from there, so they always describe the same pendant.

The API keys are read only on the server and never reach the browser. Nothing
is stored server-side: photos, sketches and files exist only in the browser
and in the request that produced them. Every error the server returns is one
plain sentence; technical detail goes to the server log only.

## Known limitations

- **No tests.** The geometry modules are pure functions and should be the
  first to get them.
- **DXF header** declares R12 but uses `LWPOLYLINE` (R13+). Most modern
  readers accept this; a strict R12-only reader may not. Test-open the first
  files in the client's own laser software.
- **Parked code:** `lib/remove-bg.ts`, `lib/remove-bg-contour.ts` and its route
  are complete but deliberately not wired in (a late-arriving remove.bg result
  made the on-screen outline change after a few seconds, which the client
  rejected). `lib/diecut-service.ts` targets a Python service that is not in
  this repo and is imported by nothing.
- **Size limits:** uploads are capped at 8 MB; the model is pinned to
  `gemini-3.1-flash-image` in `lib/gemini.ts`.
